# プロンプト最適化の運用手順

Claude への指示（プロンプト）を「一度書いて終わり」にせず、実績に基づいて継続的に改善するための仕組みです。

## 対象となるプロンプト

| ファイル | 役割 | 読まれるタイミング |
|---|---|---|
| `CLAUDE.md` | 役割・原則・品質ゲート・学習済みルール | 毎セッション自動で読み込まれる |
| `prompts/templates/design-brief.md` | 依頼を構造化するテンプレート | `/optimize-prompt` 実行時 |
| `.claude/skills/*/SKILL.md` | 個別手順（スキル） | 該当スキルの呼び出し時 |

## 改善サイクル

```
 依頼 ──▶ /optimize-prompt ──▶ ブリーフ ──▶ 制作（各スキル） ──▶ 品質ゲート
  ▲                                                              │
  │                                                              ▼
 CLAUDE.md / テンプレート更新 ◀── 承認 ◀── 改善案 ◀── /prompt-retro（learnings に記録）
```

1. **依頼時**：`/optimize-prompt <依頼内容>` でブリーフ化。重要な不明点だけ質問され、残りは仮定を明示して進む。
2. **制作中**：修正指示を出すときは「なぜ」を一言添えると、振り返りで一般化しやすくなる。
3. **完了時**：`/prompt-retro` を実行。修正指示の原因を分類し、`docs/learnings.md` に記録、改善案を before/after で提示。
4. **承認**：採用する案だけ選ぶ。適用時に `docs/prompt-changelog.md` へ記録され、コミットされる。
5. **定期見直し（月1回目安）**：`/optimize-prompt` のモードB で `CLAUDE.md` 全体を診断し、形骸化したルールを削除する。

## 運用ルール

- **昇格の基準**：同じ知見が2回以上出たら `CLAUDE.md` のルールに昇格。1回だけなら `learnings.md` に記録するに留める。
- **ルールには理由を書く**：「〜すること（理由：〜）」。理由があると状況に応じた判断ができる。
- **足すだけでなく削る**：`CLAUDE.md` は目安200行以内。超えそうなら統合・削除するか、詳細をスキルや `docs/` に移す。
- **案件固有の情報を混ぜない**：特定クライアントのブランド規定などは `prompts/briefs/` や案件ごとのファイルへ。
- **変更は必ずコミット**：git の履歴で、どの変更が効いたか後から追えるようにする。

## チームで使う場合

- 個人の好みは `CLAUDE.local.md`（git 管理外）や `~/.claude/CLAUDE.md` に書き、チーム共通の規約だけを `CLAUDE.md` に置く。
- `CLAUDE.md` の変更はPRでレビューする。PR本文に `docs/learnings.md` の根拠エントリを書く。
