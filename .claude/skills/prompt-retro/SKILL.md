# prompt-retro

プロンプト（CLAUDE.md など）を実績に基づいて育てるための振り返りです。

## 手順

1. **事実を集める**（この会話と `git log` / 差分から）
   - ユーザーから受けた修正指示・差し戻し（何を、なぜ）
   - 最初の出力と最終成果物の差
   - 品質ゲートで引っかかった項目、確認できなかった項目
   - うまくいった進め方
2. **原因を分類する**：各事象を次のどれかに分ける
   - `欠落`：ルール・情報がプロンプトになかった
   - `曖昧`：ルールはあったが解釈が割れた
   - `無視`：ルールはあったが守られなかった（→ 位置・強調・理由の追記を検討）
   - `過剰`：ルールが邪魔をした、または不要だった（→ 削除を検討）
   - `案件固有`：一般化すべきでない（→ 記録のみ）
3. **記録する**：`docs/learnings.md` に追記（書式は同ファイル冒頭）。
4. **改善案を作る**：`案件固有` 以外について、変更先と before/after を提示する。
   - 変更先の選び方：常に適用すべき規約 → `CLAUDE.md` の「学習済みルール」／ブリーフで毎回聞くべきこと → `prompts/templates/design-brief.md`／特定手順の改善 → 該当 `SKILL.md`／定型化できる新しい作業 → 新スキル（`anthropic-skills:skill-creator` を使う）
   - 同じ知見が `docs/learnings.md` に **2回以上** 出ていれば昇格（ルール化）を推奨、1回目は記録のみでもよい。
   - ルールを足すだけでなく、不要になったルールの削除も提案する。
5. **承認後に適用**：ユーザーが承認した変更だけを適用し、`docs/prompt-changelog.md` に追記し、コミットする。

## 出力形式

```
## 振り返りサマリー
- 修正指示：N件（欠落 a / 曖昧 b / 無視 c / 過剰 d / 案件固有 e）

## 改善案
### 1. <タイトル>（対象ファイル / 分類 / 根拠: learnings #ID）
before: ...
after:  ...
理由: ...

適用しますか？（番号で選択／すべて／なし）
```
