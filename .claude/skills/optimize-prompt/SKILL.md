# optimize-prompt

2つのモードがあります。引数・文脈から判断し、迷ったら A を使います。

## モードA：依頼 → デザインブリーフ

1. `prompts/templates/design-brief.md` を読み、その見出し構成で依頼を書き直す。
2. 依頼文・リポジトリ内の既存情報（README、既存ページ、ブランド資料）から埋められる項目は埋める。
3. 埋められない項目は次のように扱う：
   - 成果物を大きく左右するもの（目的、ターゲット、成果物の種類、実装形式）→ まとめて **最大4問** だけ質問する（AskUserQuestion を使い、推奨案を先頭に置く）。
   - それ以外 → 「未定（仮定：〜）」と妥当な仮定を書いて進める。
4. 完成したブリーフを提示し、着手する場合は `docs/skills-guide.md` から使うスキルの順序を1行で添える。
5. 案件として残す価値がある場合は `prompts/briefs/YYYY-MM-DD-<slug>.md` に保存する。

## モードB：既存プロンプトの改善

対象：指定されたファイル、または `CLAUDE.md` / `prompts/templates/*.md` / `.claude/skills/*/SKILL.md`。

次の観点で診断し、**差分（before/after）と理由** を提示する。ユーザーの承認なしに書き換えない。

| 観点 | チェック内容 |
|---|---|
| 明確さ | 曖昧な形容詞（「いい感じに」「モダンに」）を具体的な基準に置き換えているか |
| 検証可能性 | 完了条件が確認可能な形（数値・チェックリスト）になっているか |
| 優先順位 | 衝突しうる指示（例：装飾性 vs 軽量）の優先順位が書かれているか |
| 文脈 | 「なぜ」が書かれているか（理由のある指示は応用が効く） |
| 簡潔さ | 重複・形骸化した指示、守られていない指示がないか |
| 例示 | 判断が割れやすい箇所に良い例／悪い例があるか |
| 構造 | 見出し・表・リストで拾いやすいか、長すぎないか（CLAUDE.md は目安200行以内） |

承認されたら変更を適用し、`docs/prompt-changelog.md` に1エントリ追記する（書式は同ファイル冒頭）。
